# WinkRider 기획

> 윙크로 조향하고, 입을 벌려 가속하는 3D 카트 레이싱 웹 게임

이 문서는 지금까지 논의한 기획 내용을 정리한 것입니다. 항목마다 **확정**, **보류**(나중에 다시 결정), **논의 중**, **미정**을 구분해 표시했습니다.

## 1. 목적

- **확정** 친구들에게 링크로 공유하고 홍보하는 것이 가장 큰 목적입니다.
- 그래서 완성도, 공유 기능, "플레이하는 얼굴이 웃긴 장면"이 남는 것을 중요하게 봅니다.

## 2. 컨셉

- **확정** 카트라이더 같은 자유 조향 레이싱 게임입니다.
- **확정** 키보드 대신 웹캠으로 표정과 손동작을 인식해 조작합니다.
- **확정** 화면은 카트 뒤에서 따라가는 **3D 추격 시점**입니다.

## 3. 조작

| 조작 | 입력 | 인식 방법 | 상태 |
|---|---|---|---|
| 좌우 조향 | 왼쪽 / 오른쪽 윙크 | FaceLandmarker 표정 수치 `eyeBlinkLeft`, `eyeBlinkRight` | 확정 |
| 엑셀 | 입 벌리기 | FaceLandmarker 표정 수치 `jawOpen` | 확정 |
| 드리프트 | 주먹 쥐기 | GestureRecognizer 기본 동작 `Closed_Fist` | 확정 |
| 부스트 | 엄지 척 👍 | GestureRecognizer 기본 동작 `Thumb_Up` | 확정 (사용자가 위임해 결정) |

### 부스트를 엄지 척으로 정한 이유

- 기본으로 인식되는 동작이라 따로 학습시킬 필요가 없고 인식이 안정적입니다.
- 주먹(드리프트)에서 엄지만 펴면 되므로 드리프트에서 부스트로 넘어가는 동작이 자연스럽습니다.
- 검토한 대안: 볼 부풀리기(`cheekPuff`). 손이 필요 없고 더 웃기지만, 입을 벌린 상태(엑셀)와 동시에 할 수 없어서 제외했습니다.

### 판정 규칙 (확정)

- **조향은 두 눈의 감긴 정도 차이로 판정합니다.** 한쪽 값만 보면 윙크할 때 반대쪽 눈이 같이 찡그려지는 경우를 잘못 판정합니다.
- **양쪽 눈이 같이 감기면 무시합니다.** 자연스러운 눈 깜빡임으로 차가 멋대로 움직이지 않게 하기 위해서입니다.
- **아날로그 조향:** 살짝 감으면 살짝, 꽉 감으면 크게 돕니다. 윙크를 오래 유지하는 피로를 줄이려는 것입니다.
- **엑셀은 `jawOpen` 값에 비례합니다.** 입을 크게 벌릴수록 빨라집니다.
- **시작 전 보정:** 게임을 시작할 때 평소 표정 값을 측정해 기준으로 삼습니다. 안경, 조명, 얼굴 생김새에 따른 차이를 줄이기 위해서입니다.
- **좌우 기준은 직접 확인해서 맞춥니다.** 웹캠 화면을 거울처럼 뒤집는지에 따라 `Left`/`Right`가 체감과 다를 수 있으므로 짐작하지 않습니다.

### 대체 조작 (확정)

- 윙크를 못 하는 사람을 위해 **고개 기울이기**로 조향하는 옵션을 설정에 둡니다.
- FaceLandmarker의 `outputFacialTransformationMatrixes` 옵션으로 머리 기울기를 얻을 수 있습니다.

## 4. 게임 규칙

- **확정** 카트라이더처럼 **드리프트를 하면 부스트 게이지가 차고, 엄지 척으로 게이지를 써서 부스트**합니다. 두 조작이 하나의 흐름으로 이어지게 하려는 것입니다.
- **확정** MVP는 트랙 1개에서 랩 타임을 겨루는 **타임어택**입니다.

### 첫 트랙: 빌리지 고가의 질주 오마주 (확정)

카트라이더의 **빌리지 고가의 질주**에서 구간 흐름만 가져온 오마주 트랙을 만듭니다. 원본을 그대로 재현하지 않습니다(9장의 넥슨 트랙 디자인 미사용 원칙).

- **가져올 것 (게임 디자인 아이디어):** 출발 후 부스터 모으기 → **긴 고가 직선** → 커브 → **급경사 내리막에서의 드리프트**
- **직접 만들 것:** 실제 코스 배치, 배경, 건물, 트랙 이름
- **길이:** 한 바퀴에 1분 안팎을 목표로 합니다. 원본은 2바퀴에 프로게이머 기준으로도 1분 40초가 넘어서, 윙크하고 입을 벌린 채로 달리기에는 너무 깁니다.
- **빼는 것:** 점프대(원본에도 없음), 원본의 "인도빌드"처럼 도로 밖 지형에 올라타는 요소. 윙크 조향으로는 그런 정밀 조작이 어렵습니다.

## 5. 공유

공유 기능은 **출시 후에 결정**합니다. 아래는 검토했던 안입니다.

- **보류** 최고 속도를 낸 순간이나 충돌한 순간의 얼굴을 찍어 **결과 카드**에 넣고, 기록과 함께 공유합니다.
- **보류** 사진은 사용자가 공유 버튼을 누르기 전까지 기기 밖으로 나가지 않게 합니다.
- 홍보 포인트: 인식 모델이 브라우저에서 돌아가므로 **카메라 영상이 서버로 전송되지 않습니다.**

## 6. 범위와 로드맵 (확정)

카트라이더 전체를 한 번에 만들면 끝내기 어려우므로 단계를 나눕니다. 지금은 1단계만 설계합니다.

1. **MVP: 트랙 1개 타임어택.** 조향, 엑셀, 드리프트, 부스트, 랩 타임, 결과 카드 공유
2. 고스트(내 최고 기록과 경주), 트랙 추가 (물리 엔진 도입 검토 시작)
3. AI 상대 (늦어도 이 단계에서 물리 엔진 도입)
4. 온라인 랭킹 (이 단계부터 서버가 필요함)
5. 아이템전, 실시간 멀티플레이

### 3D 렌더링: react-three-fiber (확정)

react-three-fiber(R3F)는 Three.js를 대신하는 라이브러리가 아니라, **Three.js를 React 방식(JSX 컴포넌트)으로 쓰게 해 주는 도구**입니다.

**R3F를 고른 이유**
- 시작 화면, 보정 화면, HUD, 결과 화면을 3D 장면과 **같은 React 트리 안에서** 다룰 수 있습니다.
- 컴포넌트가 사라질 때 Three.js 객체가 자동으로 정리되어, 트랙을 바꿀 때 메모리 누수를 피하기 쉽습니다.
- 물리 엔진을 도입할 때 `@react-three/rapier`를 바로 쓸 수 있습니다.

**규칙**
- **매 프레임 바뀌는 값은 React 상태(`useState`)에 넣지 않습니다.** 카트 위치나 속도는 `useFrame` 안에서 `ref`로 Three.js 객체를 직접 바꿉니다. 상태에 넣으면 1초에 60번씩 다시 렌더링되어 게임이 버벅입니다.
- HUD처럼 React로 그리는 화면은 값을 몇 프레임에 한 번만 갱신합니다.

**로직 분리**
- **주행 로직과 인식 로직은 React와 R3F에 의존하지 않는 순수 TypeScript 패키지로 분리합니다.** R3F는 그 결과를 화면에 그리기만 합니다.
- 이렇게 하면 주행 로직을 브라우저 없이 테스트할 수 있고, "같은 입력이면 같은 결과" 테스트도 쉬워집니다.

**버전 (2026-10-22 npm 기준)**

| 패키지 | 버전 | 비고 |
|---|---|---|
| `react` | 19.3.1 | R3F 조건 때문에 **버전 고정** |
| `@react-three/fiber` | 9.8.2 | React 19 이상, 19.4 미만 필요 |
| `@react-three/drei` | 10.7.9 | fiber 9 필요 |
| `three` | 0.186.1 | |

React 19.4가 나오면 R3F가 따라 업데이트되기 전까지 맞지 않을 수 있으므로, R3F가 지원을 발표한 뒤에 함께 올립니다.

### 3D 에셋 (확정)

**트랙 도로는 에셋을 쓰지 않고 코드로 만듭니다.**
- 주행 물리가 트랙을 "3D 중심선 + 폭(리본)"으로 다루므로, 눈에 보이는 도로도 **같은 중심선 데이터로 만들어야** 화면과 충돌 판정이 정확히 맞습니다.
- 무료 레이싱 키트는 대부분 정해진 칸에 조각을 이어 붙이는 타일 방식이라 자유 곡선 트랙과 맞지 않습니다.
- 가드레일, 고가도로 교각, 차선도 중심선을 따라 코드로 배치합니다. 트랙을 바꾸면 자동으로 따라옵니다.

**카트와 배경 소품은 Kenney의 CC0 에셋을 중심으로 씁니다.**
- CC0라 출처 표기 의무가 없고 용도 제한도 없습니다.
- 같은 작가의 에셋이라 스타일이 통일됩니다.
- 부족한 것만 Poly Pizza 등에서 CC0를 우선으로 골라 채웁니다.

| 대상 | 에셋 | 비고 |
|---|---|---|
| 카트 | [Kenney Toy Car Kit](https://kenney.nl/assets/toy-car-kit) (1순위) 또는 [Kenney Car Kit](https://kenney.nl/assets/car-kit) | 내려받아 카트처럼 생긴 차, 운전자 캐릭터, glTF 포함 여부를 확인한 뒤 결정 |
| 배경 소품 (건물, 나무, 가로등, 표지판) | [Kenney City Kit](https://kenney.nl/assets/city-kit-roads) 계열 | 도로 조각은 쓰지 않음 |
| 트랙 주변 소품 (관중석, 깃발 등) | [Kenney Racing Kit](https://kenney.nl/assets/racing-kit) | 타일 방식 도로 조각은 쓰지 않음 |
| 부족한 것 | [Poly Pizza](https://poly.pizza) | 모델마다 라이선스가 다르므로 각 페이지에서 확인. "Poly by Google" 모델은 보통 CC-BY라 출처 표기 필요 |

**규칙**
- 형식은 **glTF/GLB로 통일**합니다. drei의 `useGLTF`로 불러오고, 필요하면 `gltfjsx`로 컴포넌트로 바꿉니다.
- MediaPipe 모델 파일도 내려받아야 하므로, 3D 에셋은 `gltf-transform` 같은 도구로 **압축**해 첫 로딩을 가볍게 합니다.
- 저장소에 **CREDITS.md**를 두고, 모든 에셋의 출처와 라이선스를 기록합니다. CC0도 기록합니다.
- **쓰지 않는 것:** 카트라이더에서 추출한 모델, 라이선스가 불분명한 모델, 비상업적 사용만 허용하는 라이선스(CC-BY-NC 등). 나중에 광고를 붙이는 순간 문제가 되기 때문입니다.
- 초기 개발은 단순한 도형으로 하고, 에셋은 주행이 돌아간 뒤에 입힙니다.

### 사운드 (확정)

**계속 변하는 소리는 직접 만들고, 짧게 한 번 나는 소리는 무료 음원을 씁니다.** Kenney 오디오 팩에는 엔진이나 레이싱 관련 팩이 없어서 엔진과 드리프트 소리는 직접 만듭니다.

| 소리 | 방법 | 이유 |
|---|---|---|
| 엔진 | Web Audio API로 합성 | 속도에 따라 높낮이와 음량이 계속 바뀌어야 함. 용량도 들지 않음 |
| 드리프트 타이어 마찰 | Web Audio API로 합성 (노이즈 + 필터) | 드리프트하는 동안 계속 나고, 미끄러지는 정도에 따라 세기가 바뀜 |
| 부스트, 게이지 충전, 부스터 획득 | [ZzFX](https://github.com/KilledByAPixel/ZzFX)로 생성 (`zzfx` 1.4.0, MIT) | 짧은 게임 효과음을 코드 몇 줄로 만들 수 있음 |
| 카운트다운 "삐-삐-빵" | ZzFX로 생성 | |
| 벽 충돌 | [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds) (CC0) | 충돌음은 합성하면 티가 나기 쉬움 |
| 메뉴·버튼 | [Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds), [UI Audio](https://kenney.nl/assets/ui-audio) (CC0) | |
| "Ready", "Go!" 음성 | [Kenney Voiceover Pack](https://kenney.nl/assets/voiceover-pack) (CC0) | 들어 있는 단어는 내려받아 확인 |
| 결과 화면 짧은 음악 | [Kenney Music Jingles](https://kenney.nl/assets/music-jingles) (CC0) | |

**BGM은 MVP에서 뺍니다.** 엔진과 드리프트 소리만으로도 주행감은 충분히 살고, 무료 BGM은 라이선스 조건이 까다롭기 때문입니다. 출시 전에 고르며, 후보는 다음과 같습니다(고를 때 라이선스 조건을 다시 확인).

| 출처 | 라이선스 |
|---|---|
| Pixabay Music | 출처 표기 없이 쓸 수 있는 자체 라이선스 (CC0 아님, 조건 확인 필요) |
| Incompetech (Kevin MacLeod) | CC-BY, 출처 표기 필수 |
| Freesound | 음원마다 다름 (CC0 / CC-BY / CC-BY-NC). NC는 쓰지 않음 |

**규칙**
- 소리는 **플레이 버튼을 누른 뒤에** 켭니다. 브라우저는 사용자가 클릭하기 전에는 소리 재생을 막습니다.
- **음소거 버튼과 음량 조절**을 둡니다.
- **카트라이더 효과음은 쓰지 않고, 비슷하게 흉내 내지도 않습니다.** 특히 유명한 부스터 소리.
- 모든 음원의 출처를 3D 에셋과 같은 **CREDITS.md**에 기록합니다.
- 라이브러리는 Web Audio API와 ZzFX만 씁니다. Tone.js 같은 큰 음악 라이브러리는 쓰지 않습니다.

### 주행 물리 (확정)

카트라이더의 주행감은 현실 물리가 아니라 게임이 의도적으로 만든 것입니다. 그래서 물리 엔진 없이 직접 구현합니다.

- **트랙 표현:** 트랙을 **높이가 있는 3D 중심선 곡선 + 폭**, 즉 공중에 놓인 리본 같은 도로 한 장으로 정의합니다. 카트는 항상 이 리본 위에 붙어서 달립니다.
- **경사와 고가도로:** 카트의 높이와 기울기를 그 지점의 리본에 맞춥니다.
- **벽 충돌:** 카트가 중심선에서 폭보다 멀어졌는지로 판정합니다.
- **입체 교차 대비:** 리본 위 위치를 트랙 전체가 아니라 **직전 위치 근처에서만** 찾아, 위아래로 겹친 도로를 헷갈리지 않게 합니다.
- **랩·체크포인트:** 중심선을 따라 진행한 거리로 계산합니다.
- **같은 입력이면 같은 결과:** 고스트(로드맵 2단계)에 유리합니다.

**물리 엔진이 필요해지는 기준은 경사가 아니라 "카트가 리본을 벗어나는가"입니다.**

| 요소 | 직접 구현으로 가능한가 |
|---|---|
| 오르막·내리막, 고가도로 | 가능 |
| 입체 교차 | 가능 (직전 위치 근처 탐색) |
| 점프대 (공중에 뜸) | 어려워짐 (낙하·착지 계산 필요) |
| 리본 밖 지형 (인도, 턱, 잔디) | 어려움 |
| 장애물·카트끼리 충돌 | 직접 만들어야 함 |

#### 물리 엔진 도입 계획 (확정)

직접 구현은 MVP까지만 씁니다. **트랙이 많아지면 물리 엔진 라이브러리를 도입할 예정입니다.** 트랙마다 점프대, 도로 밖 지형, 장애물처럼 리본 하나로 표현하기 어려운 요소가 늘어날 것이기 때문입니다.

- **도입 시점:** 트랙을 추가하는 로드맵 2단계부터 검토하고, 늦어도 카트끼리 충돌이 필요한 3단계(AI 상대)에서는 도입합니다.
- **후보:** Rapier (R3F용 `@react-three/rapier`, 내부적으로 `@dimforge/rapier3d-compat` 사용)
- **도입 범위:** 충돌 판정만 맡길지, 주행까지 맡길지는 도입할 때 정합니다. 카트라이더식 드리프트 같은 주행감은 물리 엔진을 쓰더라도 직접 조절해야 할 가능성이 큽니다.

MVP부터 이 계획에 맞춰 준비합니다.

- "바닥 높이 구하기"와 "벽 충돌 판정"을 **별도 모듈로 분리**해, 물리 엔진을 도입할 때 이 부분만 바꿀 수 있게 합니다.
- 트랙 데이터는 **특정 구현에 묶이지 않는 형식**으로 정의합니다. 같은 데이터에서 지금은 리본을, 나중에는 물리 엔진용 충돌 모양을 만들 수 있게 하려는 것입니다.

### 배포: Cloudflare Pages (확정)

**첫 접속 때 받는 용량이 큰 게임입니다.** 2026-10-22 기준 실제 크기:

| 파일 | 크기 |
|---|---|
| MediaPipe WASM (`vision_wasm_internal.wasm`) | 13.5MB (전송할 때는 압축되어 더 작아짐) |
| 얼굴 모델 (`face_landmarker.task`) | 3.8MB |
| 손동작 모델 (`gesture_recognizer.task`) | 8.4MB |

3D 에셋까지 더하면 첫 접속에 대략 20MB 안팎입니다. 두 번째 접속부터는 브라우저 캐시를 씁니다.

**Cloudflare Pages를 고른 이유**
- 홍보가 목적이라 접속이 한꺼번에 몰릴 수 있습니다. Vercel 무료(Hobby) 플랜은 월 전송량이 100GB라 첫 접속 20MB 기준 약 5,000명이면 찹니다. Cloudflare Pages 제한 문서에는 대역폭 한도가 없었습니다.
- Vercel 무료 플랜은 **개인 비상업 용도만 허용**해서 광고를 붙이면 유료 플랜이 필요합니다. Cloudflare Pages 제한 문서에는 이런 조항이 없었습니다.
- 무료 플랜 제한: 파일 하나 최대 25MiB(위 파일 모두 들어감), 파일 2만 개, 월 빌드 500회. 브랜치별 미리보기 배포를 지원합니다.
- **확인할 것:** Cloudflare Pages의 대역폭 무제한은 공식 문구로 확인하지 못했습니다. 가입할 때 요금 페이지에서 다시 확인합니다.

**배포 방식**
- **GitHub Actions에서 Nx로 빌드하고 결과물만 `wrangler pages deploy`로 올립니다.** 모노레포 빌드 설정을 Cloudflare 쪽에 따로 맞출 필요가 없습니다.
- WASM과 모델 파일은 직접 호스팅합니다(아래 운영 시 주의할 점).
- 모델 파일은 **경로에 버전을 넣고 캐시 기간을 길게** 잡아(`_headers` 파일), 재방문자가 다시 받지 않게 합니다.

출처: [Cloudflare Pages - Limits](https://developers.cloudflare.com/pages/platform/limits/), [Vercel - Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines)

### 운영 시 주의할 점 (확정)

- 브라우저는 **HTTPS**(또는 localhost)에서만 카메라를 허용합니다.
- 모델 파일(`.task`)은 예제처럼 Google 저장소에서 받지 말고 **직접 호스팅**하는 편이 안정적입니다.
- 저사양 기기에서는 느릴 수 있으므로 가벼운 모델이나 품질 옵션을 둡니다.

## 10. MVP 상세 설계 (확정)

사용자가 결정을 위임한 항목입니다. 기준은 MVP에 꼭 필요한 것만 넣고, 앞에서 확정한 원칙(로직 분리, 같은 입력이면 같은 결과, 판정 규칙)과 맞물리게 하는 것입니다.

### 10.1 저장소 구조

pnpm 워크스페이스 + Nx. 패키지 범위 이름은 `@winkrider`입니다.

| 프로젝트 | 역할 | 의존 |
|---|---|---|
| `apps/game` | React + Vite + R3F 게임 앱. 화면 흐름, HUD, 3D 렌더링, MediaPipe 실행, 키보드 입력 | 아래 세 패키지 |
| `packages/controls` | 인식 결과(표정 수치, 손동작)와 보정값을 받아 **조작 입력**으로 변환. 순수 TypeScript, MediaPipe 실행 코드 없음 | 없음 |
| `packages/kart` | 주행 로직. "현재 상태 + 조작 입력 + 트랙 → 다음 상태"를 계산. 바닥 높이·벽 충돌 모듈 포함. 순수 TypeScript | `track` |
| `packages/track` | 트랙 데이터 형식, 오마주 트랙 데이터, 중심선 계산(진행 거리, 직전 위치 근처 탐색, 체크포인트·랩 판정). 순수 TypeScript | 없음 |

- **조작 입력**은 카메라와 키보드가 같은 형식으로 만듭니다: 조향(-1~1), 엑셀(0~1), 드리프트(켜짐/꺼짐), 부스트(켜짐/꺼짐). 주행 로직은 입력이 어디서 왔는지 모릅니다.
- **주행 로직은 고정 간격(초당 60번)으로 계산**하고, 화면은 그 사이를 보간해서 그립니다. 기기 성능과 관계없이 같은 입력이면 같은 결과가 나오게 하려는 것입니다.
- MediaPipe를 불러오고 실행하는 코드는 `apps/game`에 둡니다. 성능 실험 결과에 따라 Web Worker로 옮길 수 있습니다.

### 10.2 화면 흐름

1. **시작 화면:** 게임 소개, 조작 방법, 플레이 버튼, 설정(조향 방식: 윙크 / 고개 기울이기, 카메라 미리보기 켜기/끄기)
2. **카메라 권한 요청**
3. **보정 겸 튜토리얼**
   - 정면을 보고 평소 표정으로 3초 → 각 표정 수치의 **평소 값** 측정
   - 왼쪽 윙크, 오른쪽 윙크를 차례로 해 보게 함 → 각 눈의 **최대 값** 기록, 판정이 맞는지, **좌우가 뒤바뀌지 않았는지 확인**
   - 입 벌리기 → `jawOpen`의 **최대 값** 기록
   - 주먹, 엄지 척을 차례로 해 보게 함 → 인식되는지 확인
   - 보정 후에는 표정 수치를 사람마다 0~1로 다시 맞춥니다: `보정값 = (측정값 - 평소 값) / (최대 값 - 평소 값)`을 0~1 범위로 자릅니다. 그러면 눈 크기, 안경, 조명이 달라도 평소는 0, 최대는 1에 가깝게 됩니다.
   - 최대 값과 평소 값의 차이가 너무 작으면(10.9절 기준) 그 표정은 제대로 인식되지 않는 것이므로 다시 해 보게 하고, 윙크라면 고개 기울이기 조향을 권합니다.
4. **카운트다운:** 3초. 기록은 카운트다운이 끝나는 순간부터 잽니다.
5. **주행**
6. **결과 화면:** 전체 기록, 랩별 기록, 최고 기록 여부, 다시 하기

### 10.3 HUD

- 속도
- 부스트 게이지와 보유 부스터 개수
- 현재 랩 / 전체 랩, 현재 랩 기록, 전체 기록

### 10.4 인식이 끊길 때

| 상황 | 처리 |
|---|---|
| 얼굴을 잠깐 놓침 | 조작 입력을 모두 0으로 둡니다. 엑셀이 꺼지므로 자연스럽게 감속합니다. |
| 얼굴을 0.5초 넘게 놓침 | 자동 일시정지하고 "얼굴이 보이지 않아요"라고 안내합니다. 얼굴이 돌아오면 3초 카운트다운 후 재개합니다. |
| 손을 놓침 | 드리프트와 부스트만 꺼집니다. 평소에도 손을 내리고 달리므로 정상 상황입니다. |
| 카메라 권한 거부, 카메라 없음 | 안내 화면을 보여 주고 키보드 모드로 플레이할 수 있게 합니다. |
| GPU 가속 실패 | CPU로 다시 시도합니다. |
| 모델 파일 로딩 실패 | 오류 안내와 다시 시도 버튼을 보여 줍니다. |

### 10.5 키보드 조작

- 개발과 디버깅에 쓰고, **카메라가 없는 사람에게도 "키보드 모드"로 열어 둡니다.**
- 키 배치는 카트라이더와 같게 합니다: ← → 조향, ↑ 엑셀, Shift 드리프트, Ctrl 부스트.
- 브레이크와 후진은 없습니다. 표정 조작에도 없기 때문입니다. 입을 다물면 감속하고, 벽에 부딪히면 벽을 따라 미끄러집니다.
- **키보드 기록은 카메라 기록과 따로 저장하고 표시합니다.** 키보드가 훨씬 쉬워서 같은 순위에 두면 불공평합니다.

### 10.6 기록 저장

- 서버가 없으므로 브라우저 저장소(localStorage)에 저장합니다.
- 트랙별, 조작 방식(카메라 / 키보드)별로 최고 전체 기록과 최고 랩 기록을 저장합니다.
- 저장소를 쓸 수 없는 환경(사생활 보호 모드 등)에서도 게임은 정상적으로 돌아가야 합니다. 그때는 기록만 저장되지 않습니다.

| `kart` | 같은 입력 순서면 항상 같은 결과, 벽 충돌, 드리프트로 게이지 충전, 부스트 |
| **입력 재생 테스트** | 실제 플레이에서 조작 입력을 녹화(JSON)해 두고, 테스트에서 재생해 같은 기록이 나오는지 확인. 주행 로직을 고쳤을 때 주행감이 바뀌었는지 알 수 있습니다. |
| `game` | 키보드 모드로 시작부터 결과 화면까지 한 바퀴 도는 E2E 테스트 1개 (Playwright) |

표정·손동작 인식 정확도는 자동 테스트로 확인하기 어려우므로 직접 플레이하며 확인합니다.

### 10.8 세부 규칙

- **랩 수: 2바퀴.** 원본 스피드전과 같고, 한 바퀴 1분 목표면 한 판에 2분 정도입니다. 표정 조작의 피로를 생각하면 3바퀴는 깁니다.
- **부스트:** 드리프트로 게이지가 가득 차면 부스터 1개를 얻고, **최대 2개까지 모아 둘 수 있습니다.** 엄지 척으로 1개를 씁니다. 원본처럼 "부스터 2개를 들고 고가 직선에 진입하는" 플레이가 가능하게 하려는 것입니다.
- **체크포인트:** 트랙에 체크포인트를 두고, 모든 체크포인트를 순서대로 지나야 랩으로 인정합니다.
- **역주행:** 진행 거리가 계속 줄어들면 "역주행" 경고를 띄웁니다. 역주행으로는 체크포인트가 인정되지 않습니다.

### 10.9 조작 수치 초기값

사용자가 결정을 위임한 항목입니다. **모두 출발점일 뿐이고, 직접 플레이하면서 바꿀 값입니다.** 쉽게 바꿀 수 있도록 판정 기준은 `packages/controls`, 게임 밸런스는 `packages/kart`의 설정 파일 한 곳에 모아 둡니다.

#### 보정

| 항목 | 초기값 |
|---|---|
| 평소 값 측정 시간 | 3초 (측정 값의 평균) |
| 보정 실패 기준 | 최대 값 - 평소 값 < 0.15 |

#### 판정 기준 (보정된 0~1 값 기준, 모두에게 같음)

| 항목 | 초기값 |
|---|---|
| 조향 세기 | 왼쪽 눈 보정값 - 오른쪽 눈 보정값 (-1~1). 방향은 보정 단계에서 확인한 좌우 기준을 따름 |
| 조향 데드존 | 차이가 0.15 미만이면 조향 0, 그 이상은 0~1로 다시 펼침 |
| 깜빡임 무시 | 양쪽 눈 보정값이 모두 0.5 이상이면 조향 0 |
| 엑셀 | `jawOpen` 보정값 0.1 미만이면 0, 0.8 이상이면 1, 사이는 비례 |
| 고개 기울이기 조향 | 5° 미만이면 0, 25°에서 최대 |
| 값 떨림 완화 | 직전 값과 섞어서 부드럽게 함 (새 값 비중 0.3) |
| 손동작 인정 | 인식 점수 0.6 이상이 **연속 2번** 나올 때 |
| 드리프트 | 주먹이 인식되는 동안 계속 |
| 부스트 | 엄지 척이 인식되는 순간 1번 발동. 다시 쓰려면 엄지 척을 풀었다가 다시 해야 함 |
| 얼굴 놓침 일시정지 | 0.5초 (10.4절) |

### 10.10 언어

- **확정** 첫 출시는 **한국어만** 지원합니다.
- **확정** 이후에 여러 언어를 추가합니다.
- **준비:** 나중에 언어를 쉽게 추가할 수 있도록, 화면에 보이는 문구는 컴포넌트에 직접 쓰지 않고 **한국어 문구 파일 한 곳에 모아 둡니다.** 번역 라이브러리(react-i18next 등)는 실제로 언어를 추가할 때 도입합니다.
- **준비:** 기록 시간 같은 숫자 표시는 브라우저 기본 기능(`Intl`)으로 형식을 맞춥니다.

### 10.11 지원 환경

- **확정** 첫 출시는 **PC 브라우저만** 지원하고, 모바일은 지원하지 않습니다.
- 휴대폰으로 접속하면 "PC에서 플레이해 주세요"라고 안내합니다.
